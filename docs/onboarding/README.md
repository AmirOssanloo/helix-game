# Onboarding

> **Entry point:** [Documentation](../README.md)

From a fresh clone to the game running in your browser with the developer panel open. Written for engineers comfortable with a terminal, Node, and a browser's developer tools — real names, real paths, real commands, so a line can be copied and run.

Read them in order the first time. After that, jump to whichever one you need.

---

## In order

| #   | Page                                                       | You get                                                              |
| --- | ---------------------------------------------------------- | -------------------------------------------------------------------- |
| 01  | [Getting started](./01-getting-started.md)                 | Everything installed, the game running, the checks passing           |
| 02  | [Tech stack](./02-tech-stack.md)                           | What's in the box and why                                            |
| 03  | [Running and debugging](./03-running-and-debugging.md)     | The developer panel, overlays, replays, the benchmark, the stress test |

**01 alone is enough to write code.** 02 tells you why the box looks the way it does. 03 matters the first time you need to reproduce a bug, tune a number, or prove a change holds frame time — which is most changes, so read it in your first week.

There is nothing to provision. No database, no containers, no credentials, no accounts. The game is one process on your machine.
