# Ability pipeline

> **Entry point:** [Architecture](./README.md)
> **See also:** [Content and registries](./content-and-registries.md) · [Commands and events](./commands-and-events.md) · [Casting a spell](./casting-a-spell-flow.md)

One pipeline casts everything: the hero's ten spells, an enemy's stun, a summon's attack, and the ability an active item in the bank carries. The hero's Invoke mechanics sit beside it as their own module and hand it an ability to cast. Names containing `foo`, `bar`, or `baz` are placeholders — the [legend](../documentation-standards.md#reading-a-placeholder) decodes each to its real shape and folder.

---

## The idea in one line

**An ability is a definition, a caster, and a target. The pipeline turns those into effects. Nothing else casts.**

Because enemies and the hero share it, an enemy's silence is tested by the same code path as the hero's, and a new enemy ability is a definition file and maybe a named effect, never a new system.

---

## The stages

Every cast passes these stages, in order, over ticks:

1. **Request.** A command names an ability and, if the targeting kind needs it, a target. For the hero that command comes from a slot key, or from an activation naming a place of the bank; for an enemy, from the selection rule its state machine runs in Chase and Attack, which tries each ability its definition lists only while the condition the entry carries holds. A unit with a form holds what its kit's slots throw; one with no form holds what its definition lists.
2. **Validate.** `domain/orders/` checks disable flags; the pipeline's request stage checks that the caster holds the ability, that the target is the kind the definition takes and exists, that a unit target is not untargetable, the cooldown clock, the mana cost, and, for a rooted caster, the range, and, for a cast whose source is a bank place whose item's active block refuses a rooted caster, the root itself. Either refuses or accepts. The checks no target changes, death, the disables, the clock, and the cost, are one pure query the request stage calls before it writes, and the HUD and the cursor call the same one over the world view, so what a square shows and what the cast does cannot disagree. Refusal drops the command and announces it. An enemy's request is not a command: the selection rule reads the disable flags itself, and a refusal is not announced, since the enemy attacks instead and would ask again every tick.
3. **Face.** A targeted ability first turns the caster toward the target at the unit's turn rate until the bearing is inside the action cone. [Movement, collision, and pathing](./movement-collision-pathing.md) owns the turn.
4. **Cast point.** The caster holds for the definition's cast point, in ticks. A stop, a new order, a stun, or death during the cast point cancels the cast, spends nothing, and starts no clock; the new order lands on the same tick, and nothing is queued for after.
5. **Commit.** Mana is spent, the cooldown clock starts, and the effects run.
6. **Backswing.** The caster is busy for the backswing, in ticks. A new order cancels the backswing without cancelling the cast.

The cooldown starts at commit, never at request. A slot that receives an ability does not start that ability's clock.

A targeted ability whose target is out of range is walked toward first, like an attack, and cast on coming into range; a caster that reaches the end of its walk still out of range has nowhere closer to go, and the cast is cancelled with nothing spent. A unit target that dies or becomes untargetable, as a lifted unit does, while the caster walks, turns, or holds its cast point cancels the cast the same way. A second cast requested in the same tick replaces the first, which had spent nothing: one order at a time, never a queue.

## Targeting kinds

| Kind      | The command carries                              | Commit happens                             |
| --------- | ------------------------------------------------ | ------------------------------------------ |
| None      | Nothing                                          | On the tick that sees the key-down         |
| Point     | A world position                                 | On the tick that sees the confirming click |
| Clamped point | A world position                             | On the tick that sees the confirming click |
| Unit      | A unit id                                        | On the tick that sees the confirming click |
| Unit or self | A unit id, which may be the caster's          | On the tick that sees the confirming click |
| Direction | A world position the caster faces toward         | On the tick that sees the confirming click |
| Vector    | The world position pressed, and the one released | On the tick that sees the release          |

A vector is aimed with two inputs: the press is where the ability lands and what its range is measured to, like a point, and the bearing from the press to the release is the line the ability lies along. A release where the press went down is a vector with no drag, and carries no line; the effect decides what that means, from what it can see at commit. A press beyond the range is walked toward like a point.

A **clamped point** is never walked toward: a position beyond the range is moved in to the range along the bearing from the caster at the request, and cast from where the caster stands. A **unit or self** ability takes a unit hostile to the caster, as a unit ability does, or the caster itself, and the effect it runs sees which from the cast context. Both are kinds of their own, so an ability that needs neither changes nothing.

**The targeting cursor is presentation state.** Pressing a slot key, or a bank key, for a point, unit, unit-or-self, direction, or vector ability opens a cursor on screen and sends nothing to the simulation. The click sends the command with the world position resolved at click time; for a vector, the button going down holds the press, resolved then, and the button coming up sends the command with the release resolved then. Escape closes the cursor and sends nothing, and so does a right click while a press is held. A cursor being open does not stop a move in progress, because the simulation does not know it is open.

## Effects

An ability definition lists effects. Each is either a **primitive** the pipeline knows, or a **named effect** the domain registry holds.

| Primitive        | Does                                                                                                                                                                                                                                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Damage area      | Applies damage of a type to units in a shape around a point. A rate content writes per second, legal only in a zone's each-tick list and never under a named effect's fields, is divided into a rate per tick once, when the world builds its spell and status records, so the primitive reads ticks and never the step rate                  |
| Apply status     | Adds a status to a unit or to units in a shape                                                                                                                                                                                                                                                       |
| Spawn projectile | Acquires a projectile that homes on a unit or travels a direction, with the list it runs on what it touches. It leaves from the anchor, or from the caster toward the anchor when the entry says so, since a unit cast anchors on its target. A homing entry the cast aimed at no unit fires nothing |
| Spawn zone       | Acquires a zone with a shape, a delay before it bites, a lifetime, and the two lists it runs: the activation list once, on the tick the delay ends, and the each-tick list on that tick and every one after it the zone is still alive for                                                           |
| Spawn unit       | Acquires units of the kind its definition names, owned by the caster, each with a lifetime and the entry's bonuses as modifier rows. An archetype is spawned as an enemy in the caster's pack, and only from a cast's own list, where the live cap is counted |
| Displace         | Moves a unit — a push, or a lift that suspends its order — and puts a status on it for the same ticks                                                                                                                                                                                                |
| Dispel, key `dispel` | Removes every entry of the target's status table whose applier's recorded side was hostile to it, and nothing the target or a friend put on it. It reads the side the entry recorded when it landed, never the applier's id, which may no longer resolve |
| Blink, key `blink_to` | Places a unit at the anchor, or on the nearest walkable ground open to its radius class, found ring by ring outward within a bounded search; no travel, no path. It bumps the unit's disjoint count |

**Whom an entry touches** is the entry's own field: the cast's target unit, every unit inside the zone running the list, or every unit a shape at the anchor covers. A shape and a zone collect units hostile to the caster only, and neither collects a corpse or a unit a status has made untargetable, so a lifted unit cannot be hit. The collection is complete before the first effect lands, so a hit that kills one unit or moves another does not change whom the entry touches. [Movement, collision, and pathing](./movement-collision-pathing.md) owns the shape tests and the displacement steps.

**A zone's shape** is one of the shapes the shape tests know, and one of them grows: an **expanding ring** has a largest radius and the ticks it takes to reach it, its radius read from the zone's age. It touches a unit on the tick its edge passes it, a unit between the edge's radius on the tick before and its radius on this one, so a unit inside the ring when it is made, or already passed, is never touched, and none is touched twice by one edge that only grows.

**Every amount is `base + perLevel × L`**, where `L` is the caster's level. A primitive is parameterised by the definition and by orb level where the definition says so, and every amount it deals, heals, or drains carries both terms, the per-level one zero where the definition has no use for it. The level is copied at commit with the orb levels, into the cast context and onto every status entry the cast's lists apply, so what a cast's burn deals three seconds later reads the level it was cast at. Anything the primitives can't express — a wall laid as segments along the cast's direction, a zone that carries units along a path — is a named effect: one function in `domain/abilities/effects/`, referenced by key. There is no scripting layer and no expression language; a bespoke behaviour is TypeScript in the domain, tested like any other rule.

**A named effect's fields are content, and may carry an effect entry of their own** — a wall's named effect decides only where each segment stands, and the segment itself is a spawn-zone entry the definition writes in full. The effect declares which of its fields hold entries, and the content tier checks each of them as it checks any entry: against the effect schema, which knows the orb level cap, and then every key, id, and frame inside it.

```typescript
// domain/abilities/effects/foo-bar.effect.ts — key 'foo-bar'
export const fooBarEffect = (
  world: World,
  cast: Cast,
  fields: FooBarFields,
): void => {
  /* … */
};
```

**One runner runs every list.** It walks the entries in the order the definition wrote them and hands each to the primitive its kind names or the function its key names, together with the **cast context**: the caster, the ability, the orb levels and the caster's level as they stood at commit, an anchor point with a facing, a direction or none, the unit the effect is aimed at or none, and the zone running it or none. The same runner runs a cast's list at commit, a zone's activation and each-tick lists, a projectile's hit list, and a status's hook and expiry lists, so an effect never learns which of them ran it, and a named effect reads its own fields and nothing else about the definition. The runner refuses nothing: the content tier resolved every key before a world existed.

Where the anchor lands follows the targeting kind — a no-target ability anchors on the caster and is aimed at it, a unit ability on its target, a point ability on the click, a direction ability on the caster, a vector ability on the press — and the orb levels and the caster's level are copied at commit, so one raised afterwards does not change what landed. The facing is the caster's, except for a vector, which faces the exact bearing from where the caster stands at commit to the press, since the action cone the turn stops inside would visibly tilt a long line. Only a vector carries a direction: the bearing of its drag, or none for a press with no drag.

## Cooldowns and cost

Each ability id has its own cooldown clock on the caster, in ticks. There is no global cooldown. A percentage reduction is read at commit and baked into the clock; it does not rewrite a clock already running. The hero's evicted spells keep their clocks in a hidden map so a re-invoked spell returns with its remaining cooldown. Mana cost and cooldown may scale with orb level; the definition holds the table and the pipeline reads the caster's current levels at commit.

**An active item's clock is the hero's, keyed by the ability id**, like any other, so moving, selling, or buying the item again touches no clock ([ADR 0011](../adr/0011-an-item-is-a-value-the-hero-holds-in-run-scope.md)). The cooldown reduction that shortens a spell's clock, the items' sum among it, shortens an active item's the same way, read at commit.

## Damage, mitigation, and statuses

`domain/combat/` owns what happens after an effect lands.

- **Damage** has a type — physical, magical, or pure — and mitigation depends on the type: physical against armour, magical against magic resistance, pure against nothing. The formula is a tunable, not a literal. Before its mitigation, a magical hit is raised by its attacker's **magic damage**, the one stat the damage door reads off the attacker: its modifier table through the one pipeline, its rows and the item totals the table references, over a base of nothing, read at the hit, a flat amount being a fraction of the hit. So an item's magic damage reaches every magical hit the hero is the source of, a spell's first hit, its burns, and a hook's damage alike, and never a summon's, whose table references zeros. A physical or a pure hit never reads it, and a source that no longer resolves adds nothing.
- **Stats are modifier-driven for every unit.** Each derived value is its base, plus the flat amounts of every modifier row for its stat, times one plus their fractions, and the stats system derives every unit's values this way each tick, walking the one key list of derived values and, for each, the live rows. A unit with no live row copies its base. The hero's base is its active form's at its current level, read every tick. A unit spawned from a definition stores its base at spawn, the definition's numbers with its tier's health multiplier applied and its regeneration per tick, derives once there so it carries real maximums on its spawn tick, and derives from that stored base every tick after, so a row a status or a source adds moves its armour or resistance on the tick it lands and a retune reaches only the units spawned after it. A maximum that falls brings health or mana down with it; one that rises fills nothing. A plain body with no definition derives nothing.
- **The modifier table** is a fixed number of rows on every unit, each one source's contribution to one stat. **Each source kind owns its rows whole:** the status system rewrites every status row from the status table each tick, the orb passives rewrite every orb row from the buffer on each refresh, and a summon's bonuses are written once at its spawn, so two sources of one kind never clear each other's rows. The table is sized for today's worst case, every status row at the most modifiers a status definition carries and every orb instance writing the most rows an orb writes, with the arithmetic beside the size. **A row past the table is refused and counted**, as a pool counts a miss: every source takes the refusal alike, the source goes without that contribution, nothing asserts, and the count is world state the checksum hashes. A derivation reads the rows in use and stops at the last of them.
- **Death** is resolved by its own system at the end of the tick, so two effects that kill the same unit in one tick produce one death event. It clears the unit's status table and announces it once. The hero goes through a death state and comes back after the respawn delay; every other unit holds its slot for a tuned delay, so what was aimed at it resolves for a moment longer, and is then released. A unit whose definition makes it indestructible stops at one health and is never taken.
- **A status** is an entry in the target's status table referencing a status definition. The definition's stack rule decides what a second application does: **refresh** resets the end tick, **stack** adds a stack and resets, **ignore** does nothing while one is active. **Every application goes through one apply path** in `domain/statuses/`, whoever calls it: an effect list, a hook, a spawn's carried statuses, or the bank. It records on the entry the applier, its orb levels and level, and its side, hostile to the holder or not, and it refuses an application from a hostile applier to a holder wearing `invulnerable`, whatever the source, a zone or a shape included, while one from the holder itself or a friend still lands.
- **A carried status** is one an enemy or summon definition lists for the unit to hold from spawn until it dies: a bash or a frost attack is a damage-dealt hook on a status the archetype carries, not an ability it casts. The spawn applies each from the unit itself, read at level one, with an end tick no tick reaches, so the row goes with the unit's death. None raises a flag, and an archetype carries at most two, so the table keeps its other rows for what is thrown at the unit.
- **A bank passive** is a status an active item's definition lists for the hero to hold while the item sits in the bank: an armour row, or a hook. The module that applies carried statuses applies them too, from the hero itself, at level one, with an end tick no tick reaches. Whenever the bank changes, and when the hero respawns with a table its death cleared, it makes the hero's table hold one entry of each status the banked items list: it keeps one already there, so no hook's ready-at tick is handed back, adds one missing, and removes one no banked item lists. A status listed as a bank passive is listed nowhere else, so its entries are known by their status id, and none raises a flag. An item in the inventory carries nothing.
- **A heal over time** is a status definition's rate of health restored to its holder every tick, into the pool its casts draw on, never past its maximum and never to a holder at zero, so a unit emptied this tick still dies at its end. It is not damage turned around: it announces nothing, runs no hook, and credits nobody. It is how an enemy mends itself, since an enemy's own regeneration runs only while it walks home.
- **Disables** are statuses that block: stun blocks every command, silence blocks every ability, root blocks movement, disarm blocks attacks. The status system derives disable flags from the status table early in every tick, right after the commands are applied; the next tick's validator reads them. What each flag refuses, ends, and closes is the disable matrix, content the world receives with the registry: the validator refuses a key or an order by its cells, the status pass ends a running order and the cast stages a cast under way where a cell says cancelled, the kit greys a slot, and the mapper closes a cursor where a cell says closed. No system writes its own list of which disable blocks what. **An activation has one column of its own**, the active-item column: silence leaves it alone, since an active item is not a spell, and stun and lift refuse it. A refusal only one item needs, such as a blink under root, is a required field of that item's active block, read by the request stage, so the column stays one column. The self-lift is a row of its own, since it raises `lifted`, `untargetable`, and `invulnerable` but not `stunned`: its cells let the four orb keys through and refuse the prepared spells, orders, and the active-item keys.
- **An expiry list** is a status definition's answer to "when this ends, do X". It is an effect list run on the holder on the tick the status pass sweeps the row, anchored where the holder stands, aimed at the holder, and cast by whoever applied the status, read at the levels the row snapshotted. It runs after the whole table has been read, so what it does lands on a unit already free of what the status set: a lift's damage reaches a holder the lift no longer makes untargetable, and it lands where the unit was dropped. Death clears the table without a sweep, so a status a death took never expires and never runs its list.
- **A damage hook** is a status definition's answer to "when this unit takes or deals damage, do X". The definition carries a damage-taken hook, a damage-dealt hook, or neither, each an effect list with an internal cooldown table, so a hook is written with the same primitives and named effects as a cast and needs no registry of its own. The damage function runs the damaged unit's taken hooks and the dealing unit's dealt hooks once per damage instance, after mitigation, with the holder as the anchor and the damaged unit as the target, so a taken hook answers on its own holder and a dealt hook answers on whom its holder hit. The caster of the list is whoever applied the status, so what the hook deals is credited where the status came from. Damage caused by a hook runs no hooks, so a hook can neither trigger itself nor ping-pong with another. **A damage-taken hook carries a required filter on the tier of the damage's source**: `any`, or the tiers it answers to, read at the hit; a source with no tier, or one that no longer resolves, meets `any` alone, and a hook with no reason to filter reads `any`. The cooldown's length is on the definition and its ready-at tick on the status table entry, so the state replays and nothing allocates. [ADR 0008](../adr/0008-damage-hooks-are-status-capabilities.md) records why a hook is a status's list and not a key or a field of its own.

## The exceptions, and where each is read

A unit is its health: no archetype field makes one immune to anything. The exceptions are three, each a status's flag or row, never a field of a definition kind, and each read where one rule already decides the thing it changes.

- **`invulnerable`** is read in two places and no more. The one damage function in `domain/combat/` reads it first: an instance aimed at a holder deals nothing and runs no hooks, the dealer's or the holder's. The one apply path in `domain/statuses/` reads it too, and refuses a status from a hostile applier. Nothing else asks: a shape or a zone still collects the holder if it can be targeted, and the two reads turn what it would do into nothing.
- **`physical_immune`** is read in the damage function alone: a physical instance aimed at a holder deals nothing and runs no hooks. Its partner is a stat, **magical damage taken**, a modifier stat read at the hit off the damaged unit's rows and totals through the one pipeline, over a base of nothing, as magic damage is read off the attacker: after its mitigation, a magical instance is scaled by one plus it. A status that makes a unit ethereal raises `physical_immune` and `disarmed` and carries a row of that stat.
- **The self-lift's let-through** is no flag: it is the self-lift's row of the disable matrix, read by the validator as it reads every row.

The AI's hold below reads `untargetable`, a flag that already exists, in the states that chase and attack. A content test holds the lists closed: only the self-lift carries `invulnerable`, only the ethereal status carries `physical_immune`, and only the named effect `gyre_lift` runs `dispel`.

## Active items

**An activation is a cast whose source is a place of the bank.** The command system hands `activate_item` to the request stage as the hero's cast of the ability the item's active block names by key, and from there it is a cast like any other: validated, faced, held for its cast point, committed, and backswung by the same stages, its clock on the hero keyed by its ability id. The cast under way records that its source is the bank, and the commit checks the bank still holds an item whose active block names the ability; one sold or moved to the inventory during the cast point cancels the cast with nothing spent, as mana that left does.

**An active block holds what only an item needs**, each field required: the ability's key, and whether a rooted hero is refused, which the request stage reads with the reason `rooted`. No ability file changes for a field an active block holds.

**Two named effects serve the active items.**

- **`gyre_lift`** chooses between two effect lists it holds by what the cast was aimed at: aimed at the caster, the self list, `dispel` and then the self-lift, so what enemies put on the hero is gone on the tick it rises; aimed at an enemy, the enemy list, a lift and the damage it lands with. It is the one list in content that runs `dispel`.
- **`refresh_clocks`** ends every clock the caster holds, those on its clock map and the kit's hidden clocks of evicted spells alike, but the clock of the ability casting it.

## The disjoint

**A unit keeps a disjoint count**, in the sub-record for what carries it, bumped by `blink_to` and by the landing of any status that raises `lifted`, the self-lift and an enemy's lift alike. A projectile aimed at a unit records its target's count at launch. The projectile system compares the two each tick, and on a mismatch the projectile stops following: it flies on to the point its target stood on that tick, ends there, touches nothing, and runs no list. A projectile aimed at a point, and a zone, are never disjointed; they are dodged by being elsewhere.

**A melee swing records its target's count when its attack point begins.** On the tick the point ends, a count that moved sends the swing through a reach check, and a target out of reach takes nothing; a count that did not move lands the swing as any melee swing lands, whether its target walked or not.

## Enemies under an untargetable hero

**The chase and attack states read an untargetable hero as hold, not home.** An enemy in either state whose target is untargetable stands where it is, turns to face it, keeps its aggro and its pack's, and starts no attack, no cast, and no walk; on the tick the hero can be targeted again, the state takes it up as it left it. An attack point or a cast aimed at the hero already ends at no cost when it turns untargetable, as every attack and cast does. The `aggro_hidden` flag is read first and still sends an enemy home, so a hero hidden from aggro and lifted at once is left, not held. The hold is a reading inside the two states in `domain/ai/states/`, not a state of its own, and it asks for no path.

## Invoke is beside the pipeline, not inside it

The hero's orb buffer, the composer, the two slots, and the hidden cooldown map live in `domain/invoke/`. They know nothing about effects. Their job is to turn key presses into **which ability** the hero throws when D or F is pressed; the pipeline's job is to throw it. The [mechanics spec](../product/specs/character-movement-and-mechanics.md) is the authority on the buffer and the slots; [Casting a spell](./casting-a-spell-flow.md) walks the handover.

Keeping them apart is what lets an enemy, and an active item, cast without owning orbs.

**Invoke is one kit.** A kit is the thing that turns a slot index into an ability request: the Invoke kit reads slots 1 to 3 as orb selection, 4 as the composer, and 5 and 6 as the prepared spells; a plain hotbar kit reads each slot as one entry of an ability list. A form definition names its kit by string key, resolved from a registry in the domain like an effect or a behaviour, so a form with a different kit is content plus one kit module, and the pipeline never learns which one is active.

## Summons

A summon is a unit like any other: it lives in the unit pool, moves, collides, takes statuses, and dies through the same systems. What makes it a summon is an owner id and a lifetime in ticks, whatever its kind. **Its kind follows the definition it names, never its caster:** a summon definition spawns a unit of the summon kind, on the hero's side, and an archetype spawns an enemy, on the enemies' side, in its caster's pack, standing where it spawned as its home. The definition owns its body and its base numbers; the bonuses the spawning entry carries are written on it at spawn as modifier rows of their own source kind, so the definition and the ability each own their half.

**Its behaviour key drives it; the hero does not order it.** A pass of its own runs the behaviour every unit's definition names, once per tick, after the cast stages and before pathing, so an order a behaviour issues is planned and walked on the tick it was issued. The hero carries no definition and is driven by commands, so the pass passes over it. A behaviour decides and issues orders through the same state machine a command does; it moves nothing itself.

**A summon ends on its lifetime, and on the same tick its owner dies**, in the death system's pass. Both are an expiry rather than a death: the slot goes back at once with no corpse, nothing is announced, and no experience is granted. The rule is the same for a hero's summon and an enemy's adds, so owner and dependants always resolve together. An add killed before then dies as any enemy does, and grants what its definition says. [ADR 0007](../adr/0007-a-spawned-unit-ends-with-its-owner.md) records why.

**Enemies an ability spawns count against the live cap.** A cast whose own list spawns archetypes is refused at the request stage, with the live-cap refusal a pack spawn gives, when those enemies would take the live enemies past the cap, so an enemy's selection rule falls back to its attack; and a cap that filled during the cast point cancels it at the commit, as mana that left does, with nothing spent and no clock started. The count is of the list's spawn entries, so the check is on what the ability spawns, never on who casts it; the content tier refuses an archetype in any list nested inside a zone, a projectile, a named effect, or a status, where no request stands to count it.

## The attack is beside the pipeline, not inside it

**An attack is not an ability.** It has no definition in the ability space, no mana, no cooldown clock, and no effect list: it is a block of numbers on the hero definition and on every archetype — what it lands, how far it reaches, how far it looks for something to hit, its two stages, the time from one shot to the next, and the projectile it fires. The rule that carries it out lives in `domain/attack/`, and the pass that runs it is registered after the behaviours and before pathing, so an attack a command or a behaviour issued is walked and faced on the tick it was issued.

It borrows everything it can. The order state machine owns the two attack states as it owns the two cast states; the turn to face is the same turn, against the same action cone; the approach is the same walk to a legal point, its goal written through the state machine as the approach point, never by the rule itself; a ranged shot is the same projectile entity a spell fires, carrying its damage as a number rather than a hit list; a melee attack, one with no projectile speed, fires nothing and lands on the target on the tick its point ends; and either way the damage lands through the same door, as physical.

**The stages** are the walk while the target is out of reach, the turn to face once it is in reach, the attack point, the shot on the tick the point ends, and the backswing. Reach is the attack's range plus the attacker's bound radius and the target's. A new order, a stop, or a cast cancels a point or a backswing through the state machine, and a cancelled point fires nothing and starts no clock; a disarm ends a point the same way but keeps the order, so the unit swings again the moment it may.

**The clock is counted from the shot, not from the point.** A shot sets the earliest tick the next shot may land, one attack time later, and the next attack point begins early enough to land on it, so two shots are one attack time apart however long the point between them is. The attack time is the definition's base attack time scaled by the unit's attack speed, which is a modifier-stack stat like movement speed and is never computed inside the attack rule.

**Two orders reach it.** An attack on a target holds one unit until it dies, becomes untargetable, or the order changes; an attack-move walks to a point and, each tick it has acquired nothing, takes the nearest enemy inside the acquire radius. While it is engaged the order is still an attack-move, holding its target and its walk point at once, so losing the target gives the walk back from where the unit then stands rather than from where it left the line. Nothing acquires while idle.

## Anti-patterns

### A spell as a system

A `tickFooSpell` system that watches for the spell's key. It bypasses validation, starts its own clock, and can't be cast by an enemy. A spell is a definition; the pipeline casts it.

### Committing on key-down for a targeted ability

Spending mana when the cursor opens, then refunding on Escape. The refund is the bug: a cancel during the refund window and a cast in the same tick double-spend. Nothing is spent until the tick that sees the click.

### An attack written as an ability

Giving the attack a definition in the ability space so it can reuse the cast pipeline. It has no mana, no cooldown clock, and no effect list, so every stage would need a special case for it, and the cast pipeline would grow a branch per stage. The attack is its own rule over the same state machine, the same turn, and the same projectile.

| Where a list runs from                                      | A cast's commit, a zone's activation and each-tick lists, a projectile's hit list, a status's hook and expiry lists; the effect cannot tell which                                                                                                                                                                                                                                                                           |
| Primitives                                                  | Damage area, apply status, spawn projectile, spawn zone, spawn unit, displace, dispel, blink                                                                                                                                                                                                                                                                                                                                               |

| A zone's clock                                              | The delay, then the activation list on the tick it ends, then the each-tick list for as long as the lifetime lasts; a lifetime of nothing activates and is gone on the same tick, which is a strike that claims ground and leaves nothing on it                                                                                                                                                                             |
| Whom an entry touches                                       | The cast's target, the zone running the list, or a shape at the anchor; a shape and a zone collect hostile units only, never a corpse and never an untargetable one; collected in full before the first effect lands                                                                                                                                                                                                        |
| Displacement                                                | The primitive applies the status it names for the duration and hands the movement over to the movement step, so a push stops at a wall and a lift's status carries the suspended order                                                                                                                                                                                                                                      |
| Bespoke behaviour                                           | A named effect: one function in `domain/abilities/effects/`, referenced by key; no scripting layer                                                                                                                                                                                                                                                                                                                          |
| A named effect's fields                                     | Content, checked by the effect's own schema; a field holding an effect entry is declared by the effect and checked by the content tier as an entry of its own                                                                                                                                                                                                                                                               |
| Cooldown clocks                                             | Per ability id, per caster, in ticks; no global cooldown                                                                                                                                                                                                                                                                                                                                                                    |
| Percentage cooldown reduction                               | Read at commit, baked into the clock, never rewrites a running clock                                                                                                                                                                                                                                                                                                                                                        |
| Evicted hero spells                                         | Keep their clocks in a hidden map                                                                                                                                                                                                                                                                                                                                                                                           |
| An active item's clock | On the hero, keyed by its ability id, so a move, a sale, or a second purchase touches no clock; shortened at commit by the same cooldown reduction as a spell's, the items' sum among it |
| Derived stats | Every unit, every tick, from its base through its modifier rows over the one key list, a copy of the base when no row is live; the hero's base from its active form, any other unit's stored at spawn and derived there once, so a retune reaches only units spawned after it; a falling maximum clamps health and mana; a plain body derives nothing |
| Damage types                                                | Physical, magical, pure; mitigation by type in `domain/combat/`, formula as a tunable; a magical hit is first raised by its attacker's magic damage, read through the pipeline off the attacker's rows and the item totals its table references at the hit, nothing from a source that no longer resolves                                                                                                                                                                                |
| The modifier table | Fixed rows on every unit, sized for today's worst case with the arithmetic beside the size; each source kind rewrites its own rows whole; a row past the table is refused and counted on the unit, by every source alike, and the count is hashed; a derivation reads only the rows in use |
| Death                                                       | Resolved once per tick by its own system: statuses cleared, announced once, the hero respawning and every other unit released after a tuned delay; an indestructible unit stops at one health                                                                                                                                                                                                                               |
| Status stacking                                             | Refresh, stack, or ignore, decided by the status definition                                                                                                                                                                                                                                                                                                                                                                 |
| Applying a status | One apply path in `domain/statuses/` for every caller; records the applier, its orb levels and level, and its side; refuses a hostile applier's status to a holder wearing `invulnerable`, from any source; the holder's own and a friend's still land |
| Disables | Stun blocks everything, silence blocks abilities, root blocks movement, disarm blocks attacks; flags derived from the status table early in every tick, right after the commands are applied, read by the next tick's validator against the disable matrix, which every reader of what a disable blocks reads |
| The active-item column | One column for every activation: silence allows it, stun and lift refuse it; a refusal one item alone needs is a required field of its active block, read by the request stage |
| The self-lift's row | Its own, raising `lifted`, `untargetable`, and `invulnerable` without `stunned`: the four orb keys let through; the prepared spells, orders, and the active-item keys refused |
| Status expiry                                               | A status definition carries an effect list run on the holder when its row is swept, anchored on the holder, aimed at it, cast by whoever applied the status, at the row's levels; it runs after the table is read, so the flags the status set are already off; a status a death cleared runs nothing                                                                                                                       |
| Damage hooks                                                | A status definition carries a damage-taken hook, a damage-dealt hook, or neither, each an effect list with a cooldown table; run by the damage function after mitigation, anchored on the holder, aimed at the damaged unit, cast by whoever applied the status; hook damage runs no hooks; the ready-at tick lives on the entry                                                                                            |
| A damage-taken hook's filter | Required, on the tier of the damage's source: `any`, or the tiers it answers to, read at the hit; a source with no tier or that no longer resolves meets `any` alone; a hook with no reason to filter reads `any` |
| Carried statuses                                            | An enemy or summon definition lists at most two, applied at spawn from the unit itself at level one until it dies; none raises a flag; a bash or a frost attack is one                                                                                                                                                                                                                                                      |
| Bank passives | Statuses an active item's definition lists while it is banked, applied by the carried-status module from the hero at level one with no end; on every bank change and on respawn the hero's table is made to hold one entry of each, kept if present, added if missing, removed if no banked item lists it; listed nowhere else, known by status id, raising no flag; an item in the inventory carries none |
| `invulnerable` | Read in two places only: first in the damage function, no damage and no hooks; and in the apply path, no hostile status |
| `physical_immune` | Read in the damage function alone: a physical instance deals nothing and runs no hooks |
| Magical damage taken | A modifier stat read at the hit off the damaged unit through the one pipeline, over a base of nothing; a magical instance is scaled by one plus it after its mitigation |
| The self-lift's let-through | Its disable-matrix row, read by the validator as every row is; no flag |
| The exceptions' lists | Closed, by a content test: only the self-lift carries `invulnerable`, only the ethereal status `physical_immune`, only `gyre_lift` runs `dispel`; no definition kind gains an immunity field |
| An activation | A cast whose source is a place of the bank, of the ability its item's active block names, through every stage as any cast; the commit cancels it, nothing spent, if the bank no longer holds an item naming the ability |
| An active block | Required fields only: the ability's key, and whether a rooted hero is refused, read at request with `rooted` |
| `gyre_lift` | A named effect choosing its self list, `dispel` then the self-lift, when aimed at the caster, or its enemy list, a lift and its landing damage, when aimed at an enemy |
| `refresh_clocks` | A named effect ending every clock on the caster's clock map and the kit's hidden clocks, but the casting ability's own |
| The disjoint | A count in the sub-record for what carries the unit, bumped by `blink_to` and by the landing of any status raising `lifted`; a projectile aimed at a unit records it at launch, and on a mismatch flies to the point the target stood, ends there, and touches nothing; point-aimed projectiles and zones are never disjointed |
| A melee swing and the disjoint | Records its target's count when the point begins; at the point's end a moved count sends it through a reach check and a target out of reach takes nothing; an unmoved count lands as any swing |
| Enemies under an untargetable hero | The chase and attack states in `domain/ai/states/` hold: stand, face, keep aggro, start no attack, cast, or walk, and take the hero up on the tick it is targetable again; `aggro_hidden` is read first and still sends them home |
| Heal over time                                              | A status definition's rate, restored to the holder's pool every tick, clamped at its maximum, never to a unit at zero; no event, no hook, no credit                                                                                                                                                                                                                                                                         |
| Invoke                                                      | `domain/invoke/`, beside the pipeline; produces the ability the slot key throws                                                                                                                                                                                                                                                                                                                                             |
| Kits                                                        | Invoke is one kit; a form definition names its kit by string key, resolved from a domain registry; a kit turns a slot index into an ability request                                                                                                                                                                                                                                                                         |
| A summon                                                    | A unit with an owner id and a lifetime; its kind follows its definition, a summon for a summon definition and an enemy in the caster's pack for an archetype; its definition owns its base numbers and the spawning entry's bonuses go on it as modifier rows |
| Enemies a cast spawns                                       | Counted against the live cap from the cast's own list: refused at request with the live-cap refusal, cancelled at commit with nothing spent and no clock started; an archetype in a nested list is refused at load |
| A summon's end                                              | Its lifetime, or the tick its owner dies, whatever its kind; both release the slot at once, announce nothing, and grant no experience                                                                                                                                                                                                                                                                                                          |
| Behaviours                                                  | One pass runs each unit's behaviour by key, once per tick, after the cast stages and before pathing; a behaviour issues orders through the state machine and moves nothing itself                                                                                                                                                                                                                                           |
| The attack                                                  | Not an ability: a block of numbers on the hero definition and every archetype, carried out by `domain/attack/`, registered after the behaviours and before pathing                                                                                                                                                                                                                                                          |
| The attack stages                                           | Walk while out of reach, turn to face, attack point, shot, backswing; reach is the range plus both bound radii                                                                                                                                                                                                                                                                                                              |
| The shot                                                    | A ranged attack fires a homing projectile; a melee attack, with no projectile speed, lands on the target on the tick the point ends and spawns nothing; both land as physical                                                                                                                                                                                                                                               |
| A cancelled attack point                                    | A new order, a stop, a cast, or a disarm ends it; nothing is fired and no clock starts                                                                                                                                                                                                                                                                                                                                      |
| The attack clock                                            | Counted from the shot: the next point begins early enough that two shots are one attack time apart                                                                                                                                                                                                                                                                                                                          |
| Attack time                                                 | The definition's base attack time scaled by the unit's attack speed, a modifier-stack stat the attack rule never computes                                                                                                                                                                                                                                                                                                   |
| Attack-move                                                 | Holds its walk point and its acquired target at once; losing the target resumes the walk from where the unit stands, never backtracking                                                                                                                                                                                                                                                                                     |
| Idle policy                                                 | Nothing acquires while idle; only an attack-move and a behaviour acquire                                                                                                                                                                                                                                                                                                                                                    |
