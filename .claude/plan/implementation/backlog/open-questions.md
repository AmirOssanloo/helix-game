| Q9 | Does the boss encounter run at 200 enemies plus a boss and adds, or lower? | The number is decided by the phase 4 headroom table, read on the worst browser's measured max tick, never the mean, because the budget is a ceiling. If the margin is under 1 ms, the cap is written lower in the phase 5 README and the ticket says so. Settled on 2026-09-20: the boss and its adds are enemies, so they count inside the cap; the table decides whether 200 holds, not whether 200 plus some number holds. Settled further the same day, with the engineering architect: the cap is a named domain constant, `ENEMY_LIVE_CAP`, declared beside the unit pool's capacity in the unit file and asserted at module load to fit inside it with the hero and a summon allowance. It is a budget number, not a designer number, so it is no tuning key. One spawn function in the domain enforces it by counting live enemy units before acquiring; the panel's spawn and the boss's summon adds both refuse through that path. A spawn is an event, not a per-tick cost, so the count is a scan until a profile asks for a counter. The projectile figure of 100 is a measurement condition, not an enforced cap. So that a lower cap is computed rather than guessed, the headroom table carries a second tick row at 100 enemies to give the per-enemy slope, and the cap becomes the largest multiple of ten whose projected max tick leaves 1 ms. The constant and the spawn path arrive with the first spawn command | P5-S21-T04 | Open until sprint 18, for the number only |
| Q21 | What is the cooldown-reduction percentage one held Whorl instance grants at each level? The spec names Whorl as section 12's percentage source and gives no number, and no page listed a tunable for it | A `whorl_cdr_per_instance` table in the tuning table beside the speed table, 1% per level per instance as a placeholder, written into the spec's section 17 table with that caveat. Each instance writes a `cooldown_reduction` modifier row, so the pipeline snapshots it at commit like any percentage source, and a later item joins by writing a row. The number is retuned in the balance pass | P1-S04-T04, P4-S17-T04 | Open, the placeholder is implemented |
| Q22 | Which orb level indexes a spell's cooldown and mana tables when the recipe holds more than one orb? Every spell has one table of seven entries, and the spells page says a two-orb spell scales with both orbs | The lowest level among the orbs in the recipe, so a spell that scales with two orbs strengthens only when both are raised, and a spell whose recipe is one orb three times reads that orb's level. Decided by the cast pipeline at commit; the cooldown module takes the level as an argument and decides nothing | P1-S04-T04, P2-S07-T03 | Open |
| Q20 | Does a move, attack, or targeted cast issued during an attack point or a cast point cancel the point, as in the source game, or is it refused? | Refused with a reason, and not queued. The ability pipeline page names the interrupts of a cast point as a stop, a stun, and death, and lists a new order as cancelling the backswing only; there is no queue to hold the order until the point ends. Built into the order state machine and the validator in P1-S02-T01 and written into the controls page. Flipping it is a one-branch change in each file and a row on the controls page | P1-S04-T04, P2-S09-T01 | Open, the proposed answer is implemented |
