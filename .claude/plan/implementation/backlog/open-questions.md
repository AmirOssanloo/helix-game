| Q9 | Does the boss encounter run at 200 enemies plus a boss and adds, or lower? | The number is decided by the phase 4 headroom table, read on the worst browser's measured max tick, never the mean, because the budget is a ceiling. If the margin is under 1 ms, the cap is written lower in the phase 5 README and the ticket says so. Settled on 2026-09-20: the boss and its adds are enemies, so they count inside the cap; the table decides whether 200 holds, not whether 200 plus some number holds. Settled further the same day, with the engineering architect: the cap is a named domain constant, `ENEMY_LIVE_CAP`, declared beside the unit pool's capacity in the unit file and asserted at module load to fit inside it with the hero and a summon allowance. It is a budget number, not a designer number, so it is no tuning key. One spawn function in the domain enforces it by counting live enemy units before acquiring; the panel's spawn and the boss's summon adds both refuse through that path. A spawn is an event, not a per-tick cost, so the count is a scan until a profile asks for a counter. The projectile figure of 100 is a measurement condition, not an enforced cap. So that a lower cap is computed rather than guessed, the headroom table carries a second tick row at 100 enemies to give the per-enemy slope, and the cap becomes the largest multiple of ten whose projected max tick leaves 1 ms. The constant and the spawn path arrive with the first spawn command. Settled on 2026-09-21: the constant is written as 200, the target, when it arrives with the pack spawn in sprint 12, so the phase 3 stress test exercises the real ceiling and nothing waits on the measurement; sprint 18 rewrites it from the table | P5-S21-T04 | Open until sprint 18, for the number only |

| Q26 | Where does a duration an effect list writes in seconds become ticks? Every other second-to-tick conversion happens once at world creation, in a record beside the definition — a spell's cast point, a status's damage — and both the simulation loop page and the definition of done say a system never multiplies by the tick rate. Found building the primitives on 2026-09-22 | One door, as built: `ticksOfSeconds` in `src/domain/definitions/`, the tier that owns every other conversion, read at the same fixed step rate, so the arithmetic is in one place and a list gives the same ticks every run.
